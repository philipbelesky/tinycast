# Music

## Invariants

- `AppCore` owns `MusicStore`, `MusicPlaybackService` and `MusicCoordinator`. Closing Music, Settings or the palette leaves playback monitoring and the gadget listener running; quitting Tinycast stops them.
- Monitoring, listening-history capture and incoming gadget connections are separate, default-off, per-Mac grants. Settings imports, iCloud sync and `settings.json` cannot enable them. The selected gadget player, the menu bar item and command customizations can appear in `settings.json`.
- Native automation targets a running player. Multiple TVTunes copies are refused rather than selecting an arbitrary version. Connecting requests macOS Automation permission. Permission failures and missing scripting support require a deliberate reconnect; other failures retry state reads after ten seconds. Recovery never replays a playback command.
- All playback effects share one bounded serial command boundary. Disconnecting invalidates queued operations and late results. An uncertain command is never replayed automatically.
- Gadget command IDs retain the most recent 256 results, including failures, across connections and source changes for one Tinycast process. A reused ID with a different command is refused. This deduplication does not survive a Tinycast restart; the firmware must retain its existing no-replay-on-reconnect behavior.
- Listening history stores observed track starts, not completed listens or audio-output confirmation. Pause/resume does not duplicate a track. Recording requires a connected player and the explicit history switch. The latest 1,000 entries are stored locally; they are neither synced nor included in backups.
- Album navigation history is separate from listening history, partitioned by player and limited to 100 albums for the process lifetime. Previous walks back; Next walks forward before choosing a different random library album. History advances only after the selected album is observed playing or paused.
- Pairing tokens live in the channel's login Keychain scope and never appear in URLs, logs, settings files or history. Reset Pairing disconnects existing clients. The current firmware uses plaintext WebSockets, so the listener is explicitly intended for a trusted LAN.
- A rating write addresses the track id captured when the user acted, never `current track`. A computed Apple Music rating is unrated. A track that is not in the library, or a player that cannot rate it, shows no stars. Clicking the current whole-star rating does not write and does not clear it. A rating failure never puts the player into the error state and is never replayed. A rating change alone does not create a listening-history entry.
- The menu bar item is a row of buttons in the bar itself, not a glyph that opens a panel. It is shown while a monitored player is playing or paused, including pause so the play button stays reachable, and it stays up for about five seconds after that stops so a track boundary does not flicker it away. It never appears before a player has had a track. It is also gated by the per-Mac "Show in menu bar" preference, which defaults on. The buttons do not dim while the service is busy: a poll every two seconds would flicker the bar.

## Surfaces

Open **Music Controls** from the launcher, its configurable alias/hotkey, or Tinycast's menu. Players shows both Apple Music and TVTunes with track/album navigation and transport. Selecting the gadget player changes which app gadget commands address; it does not start or pause either app. Listening History is searchable by track, artist, album and player.

**Rate Track ★** through **Rate Track ★★★★★** are Music commands with the same alias and hotkey treatment. They are offered in the launcher only while a player is being monitored. A command targets the monitored player that is playing, preferring the selected gadget player when both are, otherwise a paused player with a track. Typing `rate 4` or `4 stars` finds the matching command through its keywords. Success and refusal are reported with a HUD. Clicking the current whole-star rating does nothing.

The menu bar item draws its controls directly in the bar: previous album, previous track, play/pause, next track and next album, then five stars when the command-target player's track can be rated. Each is its own button, so one click acts. The stars are omitted for a track that cannot be rated, which narrows the item. Hovering a star shows the track, artist and album. The item is one image, and a click is resolved to a glyph from the pointer's screen position: macOS forwards every click on a status item at the item's centre, so the event's own location cannot tell glyphs apart. Its accessibility name stays "Music", because menu bar managers key an item's placement on it. Right-clicking the item offers **Music Controls…** and **Music Settings…**. Tinycast's own menu still has its Music Controls row.

**Settings → Music** holds the connection switches, the menu bar item, local history capture, gadget enablement, target selection and pairing token. The launch-at-login setting remains Tinycast's existing General preference. Debug uses port **8797**, independently of the installed app's **8796**, so testing cannot take over an installed gadget endpoint.

## Playback boundary

`Service/MusicAutomationRunner.swift` implements the injected `MusicPlayerControlling` boundary. TVTunes uses its `TVtn` scripting suite and stable media IDs, added in the TVTunes repository by commit `07be23d`. Apple Music uses its scripting interface and the user's saved library. Its queue playlists are named `Tinycast <session>`; only a previous playlist owned by this service instance may be deleted. Albums contain only saved library tracks, ordered by disc then track number. Same-title albums by the same album artist can merge; singles and EPs count as albums.

`MusicPlaybackService` owns sequencing, periodic state reads, album selection and command results. `MusicStore` owns channel-local preferences and `music-history.json` under `AppPaths.applicationSupport()`. A damaged or oversized history file is preserved until an explicit Clear History action. Model types do not import UI frameworks or perform I/O.

A state read, transport or rating shares one eight-second wall-clock budget: each Apple event is sent with `min(8, remaining)` and none starts once that budget is spent, failing with the existing timeout. Album enumeration and the album-queue AppleScript keep their own eight-second `with timeout`. Toggle confirmation stops after one second of real elapsed time, album confirmation after three, including the reads. An uncertain command is never replayed.

Apple Music ratings are not read on the two-second poll. One library-track lookup runs when the track id changes, after Tinycast's own write, and when the cached value is older than 30 seconds. An empty lookup means the track cannot be rated. Setting `rating` uses that same persistent id, never `current track`, and a permission error (`-54`) or an empty lookup is reported as not in the library. `rating kind` `computed` is unrated.

## TVTunes rating contract

Suite `TVtn`. The `playback state` record's integer `Rtng` is `-1` when the current track cannot be rated, `0` when it is ratable and unrated, and `1…10` half-stars otherwise. A missing `Rtng` key is treated as `-1`. `rate track` (`TVtnrate`) takes the track's stable id as the direct parameter and `to`/`Rtng` as `1…10` half-stars. It rates that id whether or not it is still current, and returns a `playback state` record. A failure is that record with `status` `error` and a human-readable `error`, changing nothing. There is no clear command. The menu shows whole stars; a 3.5 displays as three filled stars and a half star, and clicking star N sets N whole stars.

## Gadget protocol

The existing Hermes Gadget album remote can connect to `ws://<Mac IP>:8796/device` with the revealed token. The listener negotiates `album-remote-v1`, requires an authenticated JSON hello within five seconds, refuses browser-origin handshakes, bounds messages to 4 KiB and admits four concurrent connections. Pings with a payload are answered and ignored. `NetworkConnection` fails the connection on an empty ping with `EINVAL`, whatever `autoReplyPing` is set to, so a client must not send empty pings; ESP-IDF's websocket client sends one every ten seconds unless its ping interval is set. It uses macOS 26's `NetworkListener` and structured connection tasks; stopping or resetting pairing cancels them.

Commands are `toggle`, `pause`, `previous_album`, `next_album`, `previous_track` and `next_track`. State uses the existing `type`, `source`, `status`, `album`, `artist`, `track`, `error`, `can_previous` and optional `ack` fields. A `toggle` reply waits up to one second of wall-clock time, including the state reads, for the player's status to change, because Apple Music answers play/pause before its state flips; the gadget treats that reply as the confirmed glyph. Authenticated battery telemetry updates the settings readout. State continues to be sent while a player command is pending; writes and unauthenticated handshakes have deadlines. There is no HTTP management panel and no Python runtime dependency.

## Verification

`MusicTests` covers album navigation, listening-history identity and the wire schema. `MusicServiceTests` uses an injected player and clock to exercise serialized playback, duplicate and conflicting IDs, failure deduplication, delayed recovery of state reads without command replay or permission requests, explicit reconnect after denial, source changes, history persistence, damaged-history preservation and disconnects during a pending read. `MusicRemoteTests` connects real WebSocket clients to an ephemeral loopback listener and checks authentication, handshake deadlines, acknowledgements, telemetry, pings, malformed/oversized commands and repeated reconnects. `MusicConfirmationTests` exercises delayed album changes, transient fallback, matching tracks in an unrelated queue, toggle replies that precede the player's status change, and confirmation deadlines a slow reader cannot exceed. `MusicRatingTests` covers rating conversions, command targeting, the rating-read policy, menu bar presence, and an injected player for track changes between click and write, refused unratable tracks, same-star clicks, failed writes that revert without poisoning playback, and polls that must not clobber a pending rating. None of the harnesses controls a personal music player or reads pairing secrets.

Live acceptance additionally needs the signed Tinycast app's Automation permissions, one updated TVTunes instance with a loaded Plex/Jellyfin library, Apple Music library playback, and the physical gadget provisioned with Tinycast's endpoint/token. Headphone output, Mac sleep/wake and the gadget's physical controls require separate acceptance.
